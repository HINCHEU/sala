# Changelog

## Unreleased

- M8: pilot hardening. An activity log for the director, filtered by type, user and date, with who changed which score from what to what. Events now record their school. Hourly database backups and daily file backups to a separate bucket, with retention. `sala:monitor` sends Telegram alerts when a problem starts and ends (database, Redis, queue, Gotenberg, storage, disk, failed jobs, error spikes, missing backups), and `/health` serves an outside poller. Benchmarks for the grid and the results engine. New `.env` keys `TELEGRAM_ALERT_CHAT_ID` and `HEALTH_TOKEN`; run `migrate` and `sala:sync-roles` on deploy (`make deploy` does). See `docs/4-Operations-Runbook.md`.
- M7: Khmer PDF documents. Score sheet (A4 landscape), report cards for a whole class as one PDF (A4 or A5) and the honor roll, generated in the queue through Gotenberg and stored per exam and results version, with a download link on the results page. One student's card prints on the spot. Kingdom header, school logo and header text, Khmer date with a blank lunar line, Khmer numerals option and signature blocks. Run `migrate` on deploy (`make deploy` does).
- M6: results engine. Totals, averages (divisor, weighted or simple), competition ranks in the class and across the grade, mentions and pass / fail, worked out live while an exam is open and written as a versioned result when it is locked. Class result sheet with subject statistics (average, pass rate, total / girls), grade ranking, semester and year results, and each student's result history. Corrections after a lock are requests the director approves, recalculated as a new version. Lock and publish now check that the results can be (and have been) calculated. New `exams.approve-changes` permission for the director (`sala:sync-roles`).
- M5: score entry. A spreadsheet grid per class (students down, subjects across) that autosaves every 500 ms, moves with arrows / Enter / Tab, and takes a block pasted from Excel; a phone layout with one card per student. Absent (A) and exempt (E) marks, blank never 0, scores checked against the curriculum max with at most two decimals. Progress per subject, submit only when every student is filled, per-subject Excel export and import. Writes to an exam that is not open get 423; every change is logged with the old value.
- M4: teaching assignments per class with copy from last year, approvers per grade (homeroom, a role or a person), exams with a draft → open → approved → locked → published lifecycle and per-subject submit / approve / return, and the teacher's "My classes" dashboard. Closed out with authorization on exam pages and subject transitions, designated approvers who do not teach, and approval required before locking.
- M3: students (Khmer and Latin names, place of birth, photo, encrypted birth certificate / ID Poor / disability, status), guardians shared by phone so siblings get one record, teachers with the subjects they can teach and an optional sign-in link, homeroom teachers on classes, the enrollment board (add, move, remove; roll numbers in Khmer alphabetical order), student documents, search by name, code or guardian phone, and an Excel import that checks every row before a queued job saves the good ones. Registrars get the new `people.manage` permission (run `sala:sync-roles`, which `make deploy` does).
- M2: academic years with semesters (one current per school), grade levels, tracks, subjects and rooms, a one-click MoEYS template, the per-year curriculum grid with divisor and copy-from-year, mention bands per stage, and classes per year. Deletes of anything in use are refused. Route model binding now runs after the school is resolved, so another school's records 404.
- M1: schools and memberships with per-school roles (spatie teams), tenant scoping (`BelongsToSchool`, `CurrentSchool`, `ResolveSchool`), login by email or +855 phone, password reset by email or by the director, enforced 2FA for director / academic office / accountant, platform school creation with director invitation links, school settings (logo, brand colour, report header, `SchoolSettings`), school and language switchers, admin and teacher layouts.
- Phase 0: Laravel 12 + Inertia 2 + Vue 3 + Tailwind 4 scaffold, Docker Compose stack, CI, Khmer fonts and localisation, demo login.
